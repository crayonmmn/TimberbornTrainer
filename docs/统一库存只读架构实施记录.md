# 统一库存架构：第一阶段实施记录

日期：2026-11-08。基于功能提交 b500615 和实机记录提交 1f228f2 继续开发。
本阶段获准修改开发目录、构建、测试及本地提交；未获准安装 Mod、操作游戏或修改存档。

## 实现范围

采用统一描述、浏览控制器和原生目录服务，三种来源在同一服务中分派读取策略，不为相同原生库存重复建立写入适配器。

| 来源 | 发现与读取 | 能力 |
| --- | --- | --- |
| 聚居地资源统计 | IGoodService.Goods + ResourceCountingService.GetGlobalResourceCount | 只读聚合统计；预留和统一库存容量标记不适用 |
| 指定地区中心 | DistrictCenterRegistry.FinishedDistrictCenters → 中心自身 Inventories | 只读真实库存，不以地区汇总冒充自身库存 |
| 指定建筑 | 主动请求时枚举 EntityRegistry.Entities，检查实体原生 Inventories.AllInventories | 单建筑多库存分别选择和读取，不按建筑名称过滤 |

Inventories、Inventory 和 BlockObject 均不能直接作为 EntityComponentRegistry.GetAll<T>() 的注册组件参数。
实施中通过真实程序集编译核对，改用官方已绑定的 EntityRegistry；未猜测创建第二份实体集合或库存对象。
新增服务依赖 EntityRegistry、DistrictCenterRegistry、IGoodService、ResourceCountingService 和 EntitySelectionService。
实际 Bindito 初始化仍待实机验证。

## 描述与能力

- 库存身份：首次 PostLoad 生成场景标识，组合原生 EntityId 与 Inventory.ComponentName，使用长度前缀避免字符串拼接碰撞。
- 身份不取决于显示名称、排序或序号。场景重建后不复用旧身份；不写入配置或游戏存档。
- 组件名缺失或同实体组件名重复时跳过，并明确给出无法建立可靠身份的原因。
- 描述包含所属建筑名称、类型、来源、用途。施工、仓储、输出以及其他输入/输出库存分别标识；未知用途明确标记。
- 实际数量使用 AmountInStock；可用量使用 UnreservedAmountInStock；已预留物品取二者差额；预留空位使用 ReservedCapacity。
- 读取 LimitedAmount、UnreservedCapacity 和 Capacity，分别展示资源限额、可用空位和共享总容量。
- 容量状态区分有限、明确无限、未知与统计汇总。本机原生整数最大值保留原始值并标记无限状态未知，不从 int.MaxValue 推断无限容量。
- 读取、增加、减少、设置分别描述能力与原因；本阶段后面三项对所有新目标均不可用。
- 新 IInventoryCatalog 仅有发现、读取、定位和清理操作，没有库存写入接口。旧 InventoryCommands、ResourceModule 代码完整保留，新面板不调用旧写入命令。

## 资源和兼容边界

- 聚居地概览动态枚举当前原生注册资源。
- 具体库存枚举其 AllowedGoods，结合原生注册表和实际 Stock；不会把所有已注册资源都当作该库存可存入资源。
- 未注册或不在允许列表内的残留物资可读，并明确标记为残留，不提供可存入能力。
- AllowedGoods 是声明支持；当前设置可能让 LimitedAmount 为零，因此声明支持与当前可用空位分开展示。
- 地区中心自身输出库存的每资源限额与开局越限物资如实展示，不使用 GiveExistingIgnoringCapacity 等特殊发放入口。
- 地区交汇点以及带 DistrictCrossingInventory 的运输/镜像目标整栋排除；不修改运输、预留或镜像状态。
- 使用原生 Inventories 和资源注册流程的第三方建筑具备发现路径；实际第三方 Mod 未安装、未测试，不宣称兼容已通过。
- 独立自定义库存系统不适配。无法识别的库存用途没有写权限；不能凭存在原生组件推断写入安全。

## 界面及性能

- 沿用单一资源页面，库存浏览位于科研控制区之前，科研命令及其校验保持原样。
- 首次打开默认读取聚居地概览。切换建筑模式不枚举实体，需用户主动点击打开/刷新建筑列表。
- 按所属建筑归组；单击选择建筑，再使用具体库存下拉框选择输入、输出或施工库存。
- 双击建筑调用 EntitySelectionService.SelectAndFocusOn，使用游戏原生选择、高亮与镜头流程；提示为已请求，不伪造游戏响应成功。
- 列表发现不读取所有建筑的库存数量；选中后读取该具体库存的资源快照。
- 资源下拉仅浏览已读快照；主动刷新才重新读取所选库存。刷新列表根据稳定身份恢复选择，不依据旧序号。
- 从 MainPanel 通用半秒刷新中移除库存读取；科研周期刷新保持不变。没有 Tick 扫描、后台任务或全聚居地数量缓存。
- 仅保存当前列表对应的原生引用及选中库存的数据快照。切换模式、发现/读取异常或对象失效时清理；没有自动重试写入行为。

## 生命周期

- 构造和 PostLoad 不扫描实体或读取库存；PostLoad 只建立场景标识和就绪状态。
- 读取、定位前验证实体已初始化、未删除、仍有建筑组件，库存仍属于该实体且身份相同。
- 地区中心另检查其仍在原生已完成地区中心集合中。
- 读取完成后再检查对象有效性。失效或读取异常时不展示旧快照，需主动重新打开列表。
- NativeInventoryCatalog.Unload 可重复调用：取消就绪、清空目标映射和提示，并释放注入的全部场景服务引用。
- InventoryPanel.Unload 清理列表、纯数据快照和浏览器引用；新库存系统没有额外事件总线订阅或静态场景引用。
- 新场景使用新目录实例；旧实例不能经再次 PostLoad 重新连接。

# 建造模块：0.3.0 开发检查点

2026 年 11 月 7 日。此版本是可构建检查点，**不是建造模块完整交付**。

## 新的开发顺序

1. 瞬间建造与免材料独立实现，完成四种组合的实机测试。
2. 单个仓库的木材、食物、水设置、增加、减少。
3. 海狸需求、生产倍率、天气与灾害。

## 当前实际完成

- 瞬间施工已接入 `ITickableSingleton`，随游戏模拟 Tick 检查有效工地。
- 使用 `EntityComponentRegistry.GetEnabled<ConstructionSite>()` 快照，避免完工改变枚举集合。
- 必须同时满足未完工、工地 IsOn、施工库存 IsFull 才推进时间。
- 使用原生时间计算器和 IncreaseBuildTime，只补齐剩余工时，不调用 FinishNow、MarkAsFinished，不写私有字段。
- 原生 SetBuildTimeProgress→FinishIfRequirementsMet 继续负责支撑、占位、完工阻挡、事件及组件状态切换。
- 自动处理出现异常时暂停本场景建造模块，避免重复尝试。
- 两个配置字段保持独立；免材料 UI 明确禁用并标为未接入。生产倍率未实现。
- 科研和配置系统保持原实现，不引入 Harmony 或新依赖。

## 为什么没有强行接入免材料

对本机程序集进行了只读 IL 检查：

- FinishNow 会往施工库存补齐材料，同时推进工时，不能用于独立开关。
- 材料在施工期间保留于工地库存，取消和拆除参与回收；伪造补料需要完整来源记账，否则会产生免费材料回收。
- ConstructionSiteInventoryInitializer.Initialize 不只是修改容量，还会执行库存初始化和登记。
- Inventory.Initialize 对 allowed goods 使用 Add，并订阅 disallower 事件，不是清空并安全重建库存的通用 API；重复调用有重复状态风险。
- 原生构造器、验证器和物流预留之间存在关系，不能为了本轮完成而修改共享 BuildingSpec 或清除任务预留。
- 当前未找到可复用的已安装 Harmony 库，也未安装、下载其他依赖。

因此本轮只保留免材料请求策略，不允许它在运行时绕过材料检查，也没有把四组合模拟断言标为四组合功能完成。

## 构建与测试边界

- 当前源码针对现有目标游戏 DLL 构建；具体测试数量见本轮验收报告。
- ConstructionTests 对四组合请求、全局停用、缺料、暂停、已完成、阻挡、工时边界和剩余工时调用进行模拟验证。
- 模拟的完工校验不是游戏引擎测试；瞬间施工未安装、未实机验证，免材料尚无运行时实现。
- 用户当前运行中的 v0.2.0 未覆盖，没有关闭游戏、修改原始游戏文件或原有存档。

## 续开发的具体步骤

1. 为免材料选择最小切入点；必要时单独确认采用开源 Harmony 开发依赖。优先研究材料需求、施工进度门控、完工材料门控及回收来源的一致处理，而非全局跳过 Inventory.IsFull。
2. 在受控的创建工地阶段定义每工地材料策略，避免中途切换破坏已有搬运任务。明确预付材料的保留/返还规则。
3. 确认取消、拆除、复制建筑、升级、道路、无材料建筑、暂停、堆叠支撑、海狸占位与存读档的行为。
4. 免材料核心接入后再开放开关；四组合分别测试材料消耗、施工时间和完工事件次数，不能只检查建筑外观。
5. 经用户许可退出并更新 Mod 后，才做瞬间施工实测；禁止覆盖运行中的 DLL。

## 专用测试存档可行性

可行，建议通过游戏正常新建独立聚居地，不编辑存档 JSON，不使用旧存档模板：

- 一组空仓库及各自允许的木材、食物、水存储；独立标记测试区。
- 一套基础采集/生产设施、可达道路、稳定水源与足够食物。
- 固定部族，约 10～20 只海狸；确保建设工人及搬运路径可用。
- 正常方式准备基础材料；以后经过验收的工具才用于补充测试资源。
- 保留只读基准副本，每轮派生新的测试存档；存档与源码/发布包分开，不上传用户数据。
- 预留四个相同蓝图施工区，对应两项功能的四种组合，另留缺料、阻挡和取消测试区。

**建立、命名与保存测试存档前必须取得用户确认。本轮没有建立或保存该基准存档。**

# 建筑身份筛选、选择保留与主动扫描开发记录

日期：2026-11-08。以功能检查点 442ea96、实机记录 39d85cc 为基础。
本轮只修改开发目录、编译、自动化测试和本地记录，不安装 Mod、不操作游戏或存档、不推送 GitHub。

## 原因调查与筛选依据

之前 OwnerValid 仅要求 EntityComponent 已初始化、未删除且具有 BlockObject，随后检查 Inventories。
自然物体同样可能有这两个组件，导致松树、多肉植物混入建筑列表；不能通过资源名或显示名称补救。

本机原生程序集 Timberborn.Buildings.Building 公开 Spec 属性，Awake 获取对应 BuildingSpec。
只读核对官方 Blueprints.zip：原版仓库与地区中心同时有 BuildingSpec 和 BlockObjectSpec；松树、多肉植物有 BlockObjectSpec，没有 BuildingSpec。

现在要求有效的原生 Building 组件、非空 Spec、建筑 BlockObject、已初始化且未删除的实体。
这允许未完成和已完成的真实建筑，具体库存仍分别标记用途和启停状态。
使用原生 Building（含派生组件）和 Inventories 体系的 Mod 建筑具备发现路径，不采用原版名称白名单。
缺少这些身份证据的库存实体保守排除，摘要记录原因和数量；第三方独立建筑/库存体系暂不适配，不授予写权限。
地区交汇点及运输镜像继续排除，重复/缺失库存组件名继续安全排除。

## 主动扫描策略

1. 首次打开面板或任意来源列表不扫描，也不自动读取全体库存；显示“扫描资源与库存”入口。
2. 用户点击后，Scan 读取当前 IGoodService 注册资源标识并核对定义，读取原生已完成地区中心集合，快照枚举 EntityRegistry.Entities 一次。
3. 根据原生身份筛选建筑，识别其多个库存并建立当前场景目录。没有调用 Give/Take，没有读取所有库存数量。
4. 扫描报告包含场景内扫描序号、Stopwatch 实测毫秒数、注册资源数、检查实体数、原生建筑数、有可读库存的建筑数、可读库存数、有效地区中心数，以及排除对象/库存的分项计数和原因。
5. “打开建筑列表”“打开地区中心列表”和来源切换仅从既有目录生成视图，不重复枚举场景或资源全集。
6. 新建筑、资源注册或地区变化不会自动全图刷新；用户需明确“重新扫描”。目录可能陈旧，读取和定位前仍重新检查原生状态。

“可读库存数”表示结构与身份校验通过、具备原生读取接口的候选数量，不表示扫描时已逐个读取库存成功。
安全排除按对象与库存分别计数；原因使用分类聚合，不为地图上的每棵树创建长提示或缓存其引用。

## 选择保留

- 浏览模型保存实际目标 ID 和 GoodId，界面索引只用于映射当前选择，不作为身份。
- 刷新所选库存后，资源列表顺序改变仍按 GoodId 恢复。
- 重开缓存列表、重新扫描时，目标仍存在则继续读取同一库存并保留仍存在的资源。
- 资源从该库存快照消失时，仅清除资源选择并提示，保留库存目标；不会自动改选其他资源。用户可以明确重新选择。
- 目标移除、安全排除或读取失败时清除对应选择并解释原因，其他目录目标继续保留。原生读取异常会移除该库存的缓存引用。
- 切换来源不保留错误来源的选择，但保留当前场景扫描目录。
- UI 在当前建筑被再次点击时保留其具体库存选择，不无条件切回首个库存。
- 状态区域预留高度，减小普通读数提示变化造成列表按钮跳动的可能；实际布局及双击行为仍待实机复验。

## 生命周期与只读边界

- 构造、PostLoad、游戏 Tick、通用界面半秒刷新均不发起扫描。
- PostLoad 只建立场景标识与就绪状态；Unload 清除目录、资源标识、地区中心集合、扫描报告、计数和场景服务引用。
- 旧实例无法重新接入场景，新场景必须重新主动扫描，扫描序号从 1 开始。
- 缓存不保存仓储数量。读取时使用 AmountInStock、UnreservedAmountInStock、ReservedCapacity、UnreservedCapacity、LimitedAmount 等原生接口。
- 原生建筑身份、库存归属及原生完成地区中心成员关系在实际读取时重新检查；对象失效不以缓存结果伪造成功。
- 所有新适配器增加、减少、设置能力仍关闭，IInventoryCatalog 仍没有写入方法；将来开放写入也不能跳过执行前真实校验。
- 科研、需求维持、建造、旧库存命令与配置格式不变，没有新增依赖或 Harmony。

## 性能开销与限制

- 主动扫描在主线程同步执行：枚举实体约 O(E)，库存元数据约 O(I)，资源排序约 O(G log G)；只在用户点击时发生。
- 目录保存约 O(I + G + D) 元数据及匹配建筑/库存引用，只有当前场景有效，不缓存全聚居地库存数量。
- 打开列表是对缓存库存元数据过滤/排序，约 O(I log I)，并创建当前建筑行；没有全图实体访问。
- 读取所选库存仍访问当前库存资源及预留数据；聚居地概览按扫描资源目录读取原生统计。资源定义移除后读取会重新检查。
- Stopwatch 覆盖扫描与目录建立，不包含随后选择目标的库存读取和界面渲染时间。
- 大型地图的主线程停顿、列表创建成本和真实耗时尚未实测；未根据替身测试耗时声称实机性能达标。

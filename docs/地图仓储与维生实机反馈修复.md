# 地图仓储与维生实机反馈修复（2026-11-09）

源码基准 a3b6175，本轮修改未提交；不启动游戏、不改存档。本记录是源码/原生程序集调查及替身测试记录，不是新版本实机验收。

## 维生：确认事实与证据边界

- 旧 BeaverModule 用 NeedLock 捕获首次正数下限，再逐 Tick ApplyEffect 补足；既不承诺满值，也不暂停原生更新。较低基线及正常进食仍有空间，旧行为与玩家预期不一致。
- 当前 Blueprints.zip 的 Need.Beaver.Hunger / Thirst 定义：MinimumValue=-3、MaximumValue=1、StartingValue=1；DailyDelta 分别为 -0.8 / -0.7。Carrots 是独立 Nutrition 需求，范围0～1、DailyDelta=-0.05，不是 Hunger。没有把饥饿锁扩展到所有营养条。
- Timberborn.NeedSystem 的 Need.AddPoints → SetPoints，后者夹紧到原生范围。InstantEffect 经 TryRawAppraise 和 NonWastingEffectCount，再设置点数及单次更新标记；Need.Update 最多跳过下一次自然扣减，并非累加无限储备。没有发现这条路径存在超上限隐藏累计。
- Timberborn.WellbeingUI.NeedView.Update → UpdateProgress，以当前 NeedSpec.Id 调用 NeedManager.GetNeedPoints，进度条使用同一规格的上下限。用户看到的具体哪一条 UI、实际消费来源及时间顺序没有日志/录像足以完整重建；不能把“数天不进食”确认为隐藏储备缺陷。
- Appraiser.AppraiseEffects / Need.TryAppraise：非浪费正向效果在满值时无可用效果次数，不应再成为该需求的新行为动机；这不是所有进食/饮水行为的全局禁用器，也不取消已经开始的行为。资源实际消费能否达到预期仍待实机。

## 最小修复

新增 NeedMaintenance，BeaverModule 不再调用 AddEffect/旧 NeedLock。每个存活、完成初始化海狸的 Hunger / Thirst 独立接管：首次记录原更新开关，原生 DisableUpdate 暂停该需求自然更新；必要时 ResetNeed 重置到规格初始值，且仅接管初始值等于正常最大值的规格。ResetNeed 同时复用原生状态检查/事件；不直接写私有字段。

NeedManager.GetNeed 和 Need._updateEnabled 缓存反射读取，用于准确取得对象及原始开关状态；字段类型不符或访问失败停用本场景维持。当前版本由现有精确兼容门控限制，不引入 Harmony 或新依赖。关闭、全局停用、对象移除和卸载归还原状态；原来已经停用的更新不会被误开启。状态事件回调中关闭/卸载也会停止后续处理。

需求只在正常模拟 Tick 接管；暂停时尚未接管的新对象等待恢复。死亡/未初始化对象不处理。原生 SerializedNeedValueSerializer 仅保存 Name/Points，不保存更新开关；新场景不沿用对象引用，全局保持关闭，后续启用再接管。保存的点数仍是正常范围内真实值，不制造额外保存字段。

旧 NeedLock helper 保留供历史代码兼容与测试，实际 BeaverModule 已无调用；历史下限测试不能证明本次满值策略。关闭功能不回滚已经恢复的正常点数，因此随后自然下降需要时间，并非残留锁定。

## 地图仓库入口

- 使用 EntitySelectionService.SelectedObject、SelectableObjectSelectedEvent / UnselectedEvent；原生事件在选择服务更新后广播。当前对象必须通过 EntityRegistry 的精确实例/生命期检查、已完工 BlockObject、唯一启用 Stockpile 和 SingleGoodAllower 检查。
- Stockpile.Inventory 是实际储存库存。StockpileInventoryInitializer 关联 SingleGoodAllower；读取 AllowedGood，不从库存物品推断。缓存读取其私有 _inventory 仅核对绑定，歧义/未知/无配置均拒绝。
- 原生 Stockpile 和 SingleGoodAllower 在 OnEnterFinishedState 启用，退出完工状态禁用。施工库存、生产缓冲不因为有 Inventory 就被接受；其他 Mod 使用相同原生组件且满足既有安全策略时具备支持路径，未测试真实第三方兼容。
- 默认 MapInventoryPanel 仅显示当前建筑、配置物品及原生ID、数量、原生容量和可增减量，提供增减按钮。空仓库配置有效即可增减；未配置提示先在原生界面设置；名称缺失保留ID，未注册ID明确拒绝。
- 继续复用 NativeInventoryEditor 的容量/预留/暂停/全局/身份验证、至多一次原生写入和回读；增加地图选择与配置一致性复查，切换、取消、删除或配置变化不能用旧目标写入。没有更改库存原生增减算法。
- 页面订阅选择事件，仅在库存页可见时每0.5秒读当前对象以跟进同对象配置变更；不枚举全场景或全量资源。切页、关闭和卸载解除订阅并释放地图目标。科研入口独立保留。
- 历史扫描器、聚居地汇总、地区中心、多库存及旧命令底层保留；取消默认页面中的冗长列表，不把聚居地统计伪造为可写库存。

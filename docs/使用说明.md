# 海狸修改工具 v0.3.0 中文使用说明

## 适用环境与安装

Timberborn Trainer 是集成在游戏里的中文修改工具，不是独立EXE。

- 仅支持 Windows 64位 Steam Timberborn **1.1.2.8-ffc2de0-sw**（Unity 6000.5.11f1 / Mono）。没有验证其他版本、Linux或macOS。
- 使用游戏自带的官方 Mod 加载机制，`RequiredMods`为空，无需其他Mod、BepInEx、Harmony、Unity Editor或开发SDK。
- 使用前备份重要存档。不要在需要保持原样的存档中尝试一次性修改。

下载 Release 附件 `TimberbornTrainer-v0.3.0-win64.zip`。GitHub 自动附带的 Source code ZIP 是源码，不能直接安装。

退出游戏，将压缩包里的整个 `TimberbornTrainer` 文件夹放到实际“文档”文件夹下的 `Timberborn/Mods/`。Windows可在文件资源管理器中打开“文档”；如使用OneDrive重定向，以实际“文档”位置为准，不以Steam游戏目录代替。

正确结构：

```text
文档/
└─ Timberborn/
   └─ Mods/
      └─ TimberbornTrainer/
         ├─ manifest.json
         ├─ TimberbornTrainer.dll
         ├─ README.md
         ├─ LICENSE
         ├─ THIRD_PARTY_NOTICES.md
         └─ docs/
            ├─ 使用说明.md
            └─ 第三方代码来源记录.md
```

不要多嵌套一层 `TimberbornTrainer/TimberbornTrainer/`，不要把DLL放进游戏的Managed目录。更新时先把旧版本移到Mods目录之外留作备份，避免相同Mod ID `TimberbornTrainer.Core` 重复加载。不要覆盖运行中的DLL。

启动游戏，在官方 Mod 管理界面检查“海狸修改工具”已启用，按游戏提示完成必要的重新加载/重启。进入聚居地后，应能看到“修改工具”按钮；打开面板核对版本 **0.3.0**。不匹配的完整游戏版本或运行环境会禁止启用。

## 基本操作

所有修改须开启面板的“全局修改器”。每次进入新场景、读取或导入配置后全局均保持关闭，需要手动开启。面板关闭仅隐藏界面，**不会自动关闭已经启用的饥饿/口渴维持**；要停止持续性功能，请关闭对应开关或全局开关。

库存及灾害时长修改还须用游戏原生速度控制**手动暂停整个游戏**。工具不会自动暂停或恢复速度。科研和一次性建造没有这一暂停要求。

## 地图选仓与物品增减

1. 进入“资源管理 → 物品库存”。
2. 在游戏地图上单击一个**已完工的普通单物品仓库/材料堆**，先用原生界面设置要存储的物品。
3. 工具自动显示当前建筑、物品名称及原生ID、实际数量、原生容量和可增加/减少数量；不必手动选择地区、库存或资源，也不必扫描地图。
4. 暂停游戏并开启全局开关，输入正整数，点击“增加”或“减少”。核对修改前、修改后真实回读及原生库存面板。

空仓库只要已配置物品，也可增加。没有配置时会要求先在原生界面设置；不能确认唯一物品、未注册ID或规则不一致时拒绝编辑，不根据现有库存猜物品。名称缺失时保留原生ID以便识别。

数量须为 **1～2147483647** 的整数，实际还受当前容量、整数总量及预留约束。请求超过范围会**整单拒绝**并显示可操作量，不自动截断。增加不能占用已预留空位；减少不能拿走已经预留的库存。全仓有预留不一定禁止其他安全数量的操作，按对应物品原生接口判断。

切换地图仓库时自动换目标；取消选择、拆除目标、改变存储物品或对象失效时，旧目标不能继续写入。资源页可见时每半秒只更新当前对象，切页/关闭不继续读取该地图库存。

道路/住宅的施工容器、生产输入输出缓冲、地区交汇点、未完工仓库、未知用途或不唯一的配置不作为编辑目标。聚居地总量是统计，不是一个可写虚拟仓库。本版默认界面只提供地图选中单物品仓库增减，不提供跨仓库分配、多物品下拉、地区中心专用入口或设置/清空按钮；历史服务保留并不表示UI提供这些功能。

使用原生物品注册与相同仓储组件的第三方Mod有兼容路径，但没有逐一实测保证；自定义资源/库存系统不支持。

若显示“结果未确认”，原生调用可能已生效，请先检查实际库存；**不要盲目重复点击**。工具不会自动重试、回滚或补差。

## 科研点管理

入口为“资源管理 → 科研点管理”，与物品库存独立，不需要选择仓库。科研点不是普通仓库物品。

可读取当前科研点数，输入目标数值并“设置目标”，或分别“增加点数”“减少点数”。输入为 **0～1000000000** 的整数；增加/设置后的总量不能超过十亿，减少不能超过余额。零增减或相同目标不会重复调用写入。

开启全局开关后操作，结果显示修改前后真实点数；与游戏原生科研点数核对。接口异常或无法回读不会伪报成功，请先核对数值再决定后续操作。

## 立即完成所有建造

入口为“建造与生产 → 立即完成所有建造”。页面名称沿用现有导航，**没有生产倍率功能**。

一次点击取得当前实体快照，仅处理当时有效、未完工的工地，并调用原生 `ConstructionSite.FinishNow()`。不需要手动运齐材料或等待海狸施工；原版接口负责材料补足与完工流程，工具不从仓库扣取新增材料、不自行操纵运输和预留。

- 整体游戏暂停或正常运行时均可点击。
- 建筑自身暂停、占位及其他原生验证条件仍有效，不强行解除。
- 反馈区分确认完成、未完成/受阻、失效/跳过和异常；调用返回不一定表示建筑已完工。
- 没有工地时显示未检测到。再次点击仅处理当时仍符合条件的工地。
- **不是自动建造开关**。之后新放置的工地按原版施工，需再次点击才批量处理；旧配置的InstantBuilding/FreeBuilding不会触发自动完工。

用户样本中，在途海狸在完工后改送材料到仓库，未观察到任务卡死；这不是所有物流边界的保证。工具不保证无替代仓库时材料返还，不强制改海狸携带物、仓库预留或运输任务。特殊工地和其他Mod施工逻辑的覆盖有限。

## 饥饿与口渴维持

在“海狸管理”分别启用饥饿、口渴开关，再开启全局开关。两项可独立使用。

下一次正常模拟更新起，存活且完成初始化的海狸对应**基础Hunger/Thirst**恢复原版正常满值，并暂停该项自然扣减；后续新加入对象初始化完成后纳入。不添加超上限累计储备，不复活死亡海狸。

胡萝卜等食物品种的营养满足度、睡眠和其他需求是不同系统，本功能不锁定它们。已经开始的进食/饮水动作不强制取消，因此不能把“基础需求满值”理解为所有食物/水消费必定为零。

关闭某一项或全局开关会归还原来的需求更新状态，按原版恢复变化，不把正常满值回滚成开启前的较低值。暂停游戏时新开启状态可能要等恢复模拟才接管。重新加载后不会自动全局启用；先确认供给安全，再决定是否开启。

## 天气与灾害总时长（实验性）

“天气管理”和“灾害管理”共用同一编辑区；不是两套独立灾害控制器。

1. 点击“刷新天气”，读取本周期及已选灾害。
2. 手动暂停、全局启用。
3. 输入 **1～1000整数天**，点击“设置本周期灾害总时长”。

修改的是**当前周期已经选定的干旱或恶水总时长**，不是从现在开始的剩余天数。当前仍在正常季节时，也只是编辑本周期已经选定的灾害时长，不立即触发它。不能把周期结束日期缩短到已经到达的日期之前。

工具同步当前版本的原生灾害时长及周期结束缓存；未知灾害或其他Mod增加的周期服务拒绝修改。不会切换天气类型、强制开始/结束灾害、覆盖天气效果或控制未来周期。此项仍保留实验标识，先在备份存档测试倒计时、自然结束及保存重载。

这是一次性真实状态修改，不写入工具配置；“恢复默认”不会撤销已改时长，正常保存游戏可能保留它。

## 配置与恢复默认

配置位于 `%LOCALAPPDATA%/TimberbornTrainer/config.json`，与游戏存档分离；导入导出文件位于同目录的 `Exchange/`。界面配置区域悬停可查看本机实际路径。

- “保存配置”保存当前偏好；“读取配置”读取已有文件并保持全局关闭。
- 展开“配置导入与导出”，填写独立 `.json` 文件名，不填写路径，也不要使用 `config.json`。导出创建交换文件，导入读取交换文件并保持全局关闭。
- “恢复默认”关闭持续性偏好；如要持久化，随后保存配置。
- 不撤销已经修改的库存、科研、建筑或灾害时长，不重放一次性命令。配置中的旧建造字段只为兼容解析保留。

## 卸载

先关闭全局开关及两项维生，确认已恢复正常供给，再按需要保存游戏并正常退出。通过官方Mod管理界面停用工具，并将 `文档/Timberborn/Mods/TimberbornTrainer` 移出Mods目录或删除。

无需删除游戏原始文件。个人配置可保留；确需重置时，仅处理本工具的LocalAppData配置目录。卸载不会撤销已经保存到游戏的资源、点数、建筑和灾害时长修改，恢复原状须使用之前的存档备份。

## 常见问题

**Mod没有显示？** 检查下载的是安装附件而非Source code，目录层级正确、manifest与DLL同层，原生Mod管理器已启用且没有重复Mod ID。退出游戏后再更新文件。

**全局开关不能开启？** 核对Windows64位、完整游戏版本及Unity版本；最低版本字段不表示支持所有后续版本。不要修改游戏程序集绕过检查。

**选中仓库却不能编辑？** 检查已完工、已配置唯一物品、不是施工/生产库存。某些第三方仓库有不同实现，本版可能安全拒绝。

**增加失败？** 手动暂停、全局启用、重新选仓；核对当前可增加数量和原生预留，输入合法正整数。容量已满或有输入预留时不能强加。

**减少失败？** 可减少量是未预留库存，不是面板总量；不能拿走已被运输等系统预留的资源。

**为什么没有设置目标或清空按钮？** 当前简化地图库存界面只提供增减；不要把历史开发服务能力当作本版默认按钮。

**科研入口在哪？** “资源管理”页顶部“科研点管理”，不在仓库物品列表里。

**开启维生后营养条仍下降？** 功能维持基础饥饿和口渴，食物种类满足度等其他条不受影响；已开始的动作也可能完成。不是无限满足所有需求。

**关闭面板后维生还在？** 隐藏面板不等于关闭全局或开关；请显式关闭所需功能。

**建造按钮没完成某个工地？** 检查建筑自身暂停和原版阻挡，查看结果统计。工具不会自动重试或绕过这些条件。

**天气没有立即变成干旱？** 本版只有本周期灾害总时长编辑，没有即时天气切换。

**需要反馈问题？** 提供游戏完整版本、Mod版本、操作步骤、结果提示和必要日志片段。Unity日志通常位于 `%USERPROFILE%/AppData/LocalLow/Mechanistry/Timberborn/Player.log`；以实际日志位置为准。不要公开完整存档、个人路径或含隐私的完整日志。

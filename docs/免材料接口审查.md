# 免材料接口审查（目标游戏 1.1.2.8）

审查日期：2026-11-07。依据本机合法游戏程序集的元数据与 IL；未执行游戏程序集、未改写它们，也未安装补丁依赖。

## 原生链路

1. ConstructionSiteInventoryInitializer.Initialize 从 BuildingSpec.BuildingCost 取得各物品数量，由 InventoryInitializerFactory 创建施工库存。该方法是接口实现的 final virtual 方法，不是可直接派生覆盖的费用策略。
2. InventoryInitializer.Initialize 调用 Inventory.Initialize，并登记到实体的 Inventories。重复初始化现有库存不是安全的费用修改接口。
3. ConstructionJob.StartConstructionJob 先尝试施工，否则查找材料。RemainingRequiredGoods 使用施工库存的允许物品、库存数量和未预留容量决定需求。
4. StartNeededMaterialsDelivery 通过搬运行为预留来源库存数量（ReserveNotLessThanStockAmountConsuming）和目标容量（ReserveCapacity）。清空工地或改容量并不能证明这些预留被正确解除。
5. HasMaterialsToResumeBuilding 按材料进度与工时进度的分段比较控制施工。BuildExecutor.Launch 和 Tick 都会检查它。只改变界面材料需求不能解除这层门控。
6. IsReadyToFinish 要求施工库存 IsFull、工时满足、海狸占位允许且 IsOn。FinishIfRequirementsMet 还检查未完成状态与完工阻挡，最后调用原生 MarkAsFinished。
7. ConstructionRegistrar.OnExitUnfinishedState 从原生任务登记表移除工地，并解除优先级事件订阅。保持原生状态转换有利于保留这些清理过程，但不能仅凭静态链路断言物流已实测正常。
8. RecoverableGoodProvider 遍历实体所有库存，将实际 Stock 乘以每个 IRecoverableGoodMultiplier 的结果后加入回收登记。ConstructionSiteRecoverableGoodMultiplier 对未完成工地返回 1，对已完成工地的施工库存使用拆除回收率。

## 新确认的回收接口与限制

RecoverableGoodProvider 提供公开 DisableGoodRecovery / EnableGoodRecovery，但它影响整栋建筑的所有库存。
不能用它消除伪造施工材料的回收：这还会抹掉真实交付材料、生产库存等合法回收。
IRecoverableGoodMultiplier 可限定库存，但现有乘法系数也不能单独表达混合真假材料、按物品来源扣除和部分真实交付的完整账目。

## 候选方案审查

| 方案 | 结论 |
| --- | --- |
| FinishNow | 同时填料和推进工时，破坏开关独立性，禁止使用 |
| 填满工地或仓库 | 虚构材料，取消及拆除有免费回收风险，禁止使用 |
| 重置既有 Inventory 或共享 BuildingSpec | 可能破坏登记、订阅、其他工地与物流预留，禁止使用 |
| 只跳过 HasMaterialsToResumeBuilding | 完工仍要求库存满，需求与搬运仍在，不完整 |
| 全局修改 Inventory.IsFull | 会影响生产/仓库等无关库存，禁止使用 |
| 新工地创建时使用零费用库存 | 候选研究方向；还必须保留原有正常工时、逐工地持久化费用政策，处理读档、关闭开关和移除 Mod 后的行为，当前没有安全完整实现 |
| 精确的工地级 Harmony 补丁 | 可能需要同时覆盖需求、进度和完工的材料门控；必须先证明既有搬运任务的安全边界、每工地政策与异常撤销。当前没有安装 Harmony，也没有为了交付版本号引入未经验证补丁 |

## 本轮决定

免材料运行时保持未实现、UI 禁用。导入 FreeBuilding=true 不绕过材料检查。
本轮不提供材料消耗、取消返还或物流清理的虚假模拟通过结论。
后续应先证明新工地政策及存读档的一致性，再决定是否申请安装最小补丁依赖；即使采用 Harmony，也不应接管正常材料工地的搬运预留。

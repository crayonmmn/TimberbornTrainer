# 生存功能初始化故障修复记录

日期：2026-11-07。目标游戏：1.1.2.8-ffc2de0-sw。基于提交 1f398ad 修复。

## 原因及依据

旧 BeaverModule 构造器直接请求 BeaverCollection；本机官方 BeaversConfigurator 未绑定该类型。
BeaverPopulation 在其构造器内部创建并私有持有该集合，依靠 CharacterCreatedEvent / CharacterKilledEvent 更新。
公开且可编译的类型不代表能通过 Bindito 注入。之前 151 项模拟断言没有覆盖实际模块依赖及场景加载。

已只读核对当前程序集：CharactersConfigurator 将 CharacterPopulation 注册为场景单例，公开 Characters。
原生 AreaNeedApplier 同样使用该角色入口，再调用 NeedManager.ApplyEffect。
Mortal.InitializeEntity 发出角色创建事件时，实体初始化流程可能尚未结束；不能立即操作新生对象的需求。

## 本次最小变更

- BeaverModule 依赖改为 CharacterPopulation；不注册或创建额外 BeaverCollection，不反射访问原生私有字段，不引入 Harmony。
- PostLoad 阶段只订阅已加载 TrainerState 的 Changed 事件，并设置场景就绪标记；不枚举实体、不修改需求。
- Tick 获取 Characters 的局部数组快照。只接纳有效且存活的 Character，要求 EntityComponent 已初始化且未删除，并具有有效 Beaver、NeedManager。
- 尚未初始化的出生对象被跳过，待后续 Tick 重新读取原生集合后纳入；不保存独立长期角色名册。
- 原生效果可能触发回调，因此第二项需求处理前重新检查对象有效性及全局开关。回调卸载场景或关闭全局后立即停止。
- 死亡或移除对象的需求基线按当前有效集合清理。关闭单项只清理对应基线，全局关闭清理两项；原生需求更新从未被停用，仍保持原有补偿机制。
- Unload 先禁止 Tick，解除对实际订阅状态对象的事件订阅，清理基线和计数，并释放 Session、Population、State 引用。重复卸载安全；旧实例不能重新挂接已卸载场景。
- 配置尚未就绪或需求处理异常时仅停用本场景需求维持，不在循环中自动重试。

## 验证

Release 构建成功，零错误、零警告。总计 173 项断言通过：配置 35、科研 40、建造 36、生存命令与策略 40、BeaverModule 生命周期 22。

新测试直接编译实际 Modules/BeaverModule.cs，使用单独测试程序集中的游戏接口替代实现，覆盖：

- PostLoad 前不访问实体，重复 PostLoad 不重复订阅。
- 死亡、已删除、未完成初始化、已销毁、缺少必要组件的对象跳过。
- 出生与初始化时间差，后续 Tick 纳入新对象。
- 原生效果回调改变角色集合时，快照遍历不受破坏；新增对象留待下次 Tick。
- 独立关闭、全局关闭和回调期间关闭后的停止行为；不回滚补偿值。
- 重复 Unload、解除订阅、释放场景引用；新场景采用新实例及新基线。
- 异常后暂停、不自动重试，初始化状态缺失时安全停用。

这些是自动化替代接口测试，不会执行游戏程序集，不是 Unity、Bindito 容器或真实场景测试。
构建也不能证明正确加载。当前仅能报告代码层根因修复及静态、单元验证通过。

## 尚待授权的实机验收

先由用户处理当前错误界面并退出，确认后才安装修复版和启动游戏。
依次验证专用新局、已有专用测试存档、返回主菜单后再次进入、出生后初始化、全局关闭及场景卸载。
死亡或移除清理优先用模拟测试和自然事件验证，不故意让测试海狸死亡。
还需确认容器不会暴露后续其他依赖错误，以及角色枚举数量、需求真实值和关闭后的正常变化。

本轮没有安装或覆盖用户 Mod，没有启动、关闭、重启游戏，没有读取或修改存档内容，没有推送 GitHub。
科研、库存、建造核心、NeedLock 补偿算法及配置格式均保持不变；v0.2.0 稳定产物继续保留。
